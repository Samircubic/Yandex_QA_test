# Автотесты API Яндекс.Диска

## О проекте

Проект содержит функциональные автотесты REST API сервиса Яндекс.Диск.

Цель проекта проверить основные операции над ресурсами Диска:
создание, получение информации, перемещение и удаление.

## Используемые инструменты

Python 3, pytest, requests

## Запуск тестов

Запуск всех тестов:

```bash
pytest -v
```

`pytest` автоматически ищет тестовые файлы с именами вида `test_*.py`
в каталоге `tests/` и запускает функции, названия которых начинаются с
`test_`.

## Планируемое покрытие

| ID | Проверка | Метод | Ожидаемый результат |
| --- | --- | --- | --- |
| `TC-001` | Создание папки в `app:/` | `PUT` | Папка создана, ответ `201 Created` |
| `TC-002` | Получение метаинформации существующей папки | `GET` | Ответ `200 OK`, имя и тип ресурса корректны |
| `TC-003` | Получение несуществующего ресурса | `GET` | API сообщает, что ресурс не найден |
| `TC-004` | Перемещение пустой папки | `POST` | Ответ `201 Created`, ресурс доступен по новому пути |
| `TC-005` | Перемещение несуществующего ресурса | `POST` | API сообщает об отсутствии исходного ресурса |
| `TC-006` | Удаление пустой папки | `DELETE` | Ответ `204 No Content`, ресурс больше недоступен |
| `TC-007` | Удаление несуществующего ресурса | `DELETE` | API сообщает, что ресурс не найден |
| `TC-008` | Жизненный цикл ресурса: создать, прочитать, переместить и удалить | `PUT`, `GET`, `POST`, `DELETE` | Состояние ресурса корректно меняется после каждой операции |
| `TC-009` | Перемещение непустой папки с обработкой асинхронного ответа | `POST`, `GET` | При ответе `202 Accepted` статус операции проверяется до `success`; после завершения ресурс доступен по новому пути |

## Принципы тестирования

- Все ресурсы создаются только внутри `app:/`.
- Каждый тест использует уникальное имя ресурса, чтобы его результат не зависел
  от данных другого теста или другого запуска.
- Созданные тестами данные удаляются после выполнения проверок; ошибка очистки
  не скрывается и должна приводить к ошибке теста.
- Проверяются не только HTTP-коды, но и значимые поля ответов и итоговое
  состояние ресурса.
- Основные тесты не должны зависеть от порядка запуска.

## Асинхронные операции

Согласно документации Яндекс.Диска, перемещение или удаление непустой папки
может выполняться асинхронно. Для такой операции API возвращает
`202 Accepted` и ссылку на получение статуса. Если API отвечает таким образом,
проект проверяет завершение операции через запрос статуса и ожидает результат
`success`.
