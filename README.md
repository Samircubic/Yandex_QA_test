# Автотесты API Яндекс.Диска

## О проекте

Проект содержит функциональные автотесты REST API сервиса Яндекс.Диск.

Цель проекта проверить основные операции над ресурсами Диска:
создание, получение информации, перемещение и удаление.

## Используемые инструменты

Python 3, pytest, requests

## Тестовый набор

В проекте реализованы позитивные, негативные и сценарные проверки.

- Позитивные тесты проверяют основные операции API: `PUT`, `GET`, `POST`,
  `DELETE`.
- Негативные тесты проверяют ожидаемые ошибки: отсутствие ресурса и конфликт
  при перемещении в занятый путь.
- Сценарные тесты проверяют последовательную работу нескольких методов,
  повторяемость жизненного цикла ресурса и обработку асинхронной операции.

Связь требований, тест-кейсов и автотестов вынесена в `RTM.md`.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Перед запуском тестов нужно передать OAuth-токен тестового аккаунта через
переменную среды `YANDEX_DISK_TOKEN`.

```bash
read -s "YANDEX_DISK_TOKEN?OAuth token: "
export YANDEX_DISK_TOKEN
printf '\n'
```

После завершения работы переменную можно удалить:

```bash
unset YANDEX_DISK_TOKEN
```

## Запуск тестов

Запуск всех тестов:

```bash
pytest -v
```

Запуск отдельных групп:

```bash
pytest -m positive
pytest -m negative
pytest -m scenario
```

Также можно запускать отдельные файлы:

```bash
pytest tests/test_positive_resources.py
pytest tests/test_negative_resources.py
pytest tests/test_resource_lifecycle.py
```

Проверить, что pytest видит тесты, можно без запуска сетевых запросов:

```bash
pytest --collect-only -q
```

## Структура проекта

- `disk_client.py` — клиент для вызовов REST API Яндекс.Диска.
- `tests/conftest.py` — подготовка клиента, уникальных путей и очистки.
- `tests/test_positive_resources.py` — позитивные проверки.
- `tests/test_negative_resources.py` — проверки ожидаемых ошибок.
- `tests/test_resource_lifecycle.py` — длинные сценарии работы с ресурсом.
- `RTM.md` — матрица соответствия требований, кейсов и автотестов.
- `pytest.ini` — настройки поиска тестов и маркеров.

## Принципы тестирования

- Все ресурсы создаются только внутри `app:/`.
- Каждый тест использует уникальное имя ресурса, чтобы его результат не зависел
  от данных другого теста или другого запуска.
- Созданные тестами данные удаляются после выполнения проверок; ошибка очистки
  не скрывается и должна приводить к ошибке теста.
- Проверяются не только HTTP-коды, но и значимые поля ответов и итоговое
  состояние ресурса.
- Основные тесты не должны зависеть от порядка запуска.

## Асинхронные операции

Согласно документации Яндекс.Диска, перемещение или удаление непустой папки
может выполняться асинхронно. Для такой операции API возвращает
`202 Accepted` и ссылку на получение статуса. Если API отвечает таким образом,
проект проверяет завершение операции через запрос статуса и ожидает результат
`success`.

## Реализованный API-клиент

В проекте реализован класс `YandexDiskClient` для обращения к REST API
Яндекс.Диска. Клиент является самостоятельным модулем и не зависит от
`pytest`: его можно использовать как в будущих автотестах, так и в отдельном
сценарии работы с API.

Клиент получает OAuth-токен при создании объекта, добавляет его в заголовок
`Authorization` и отправляет запросы к `https://cloud-api.yandex.net/v1/disk`.
Пути ресурсов автоматически ограничиваются папкой приложения `app:/`;
обращение к пути за её пределами клиент не отправляет.
Результат каждого вызова возвращается как объект `requests.Response`.
Клиент не сравнивает коды ответа с ожидаемыми значениями и не принимает
решений о результате проверки: эта логика относится к вызывающему коду или
автотестам.

| Метод клиента | HTTP-метод | Операция API |
| --- | --- | --- |
| `create_folder(path)` | `PUT` | Создание папки по указанному пути |
| `get_resource(path)` | `GET` | Получение метаинформации о ресурсе |
| `move_resource(source_path, destination_path)` | `POST` | Перемещение файла или папки |
| `delete_resource(path)` | `DELETE` | Удаление файла или папки |
| `get_operation_status(operation_url)` | `GET` | Получение статуса асинхронной операции |

Для сетевых запросов используется одна HTTP-сессия. После работы с клиентом
сессию можно закрыть методом `close()` или использовать клиент через
конструкцию `with`.
